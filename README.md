# Personal Site

My personal landing page, built with [Hugo](https://gohugo.io/) and deployed on [Firebase Hosting](https://firebase.google.com/products/hosting).

**Live:** [ciroluciotecce.it](https://ciroluciotecce.it)

## What it is

A simple, static one-page site — just my name, title ("Software Engineer"), a short bio, and links to my social profiles (GitHub, LinkedIn, Instagram, Email). No blog, no posts, no dynamic content. Just a digital business card.

## Tech stack

| Component | Choice |
|---|---|
| Static site generator | [Hugo](https://gohugo.io/) (v0.121+) |
| Theme | [LoveIt](https://github.com/dillonzq/LoveIt) (git submodule) |
| Hosting | Firebase Hosting (`clt-personal-site` project) |
| CI/CD | GitHub Actions (auto-deploy on push to `main`) |

## Local development

### Prerequisites

1. **Hugo** (extended version, v0.121 or later) — [install instructions](https://gohugo.io/getting-started/installing/)
2. **Git** (for the theme submodule)

### Setup

```bash
# Clone the repo (if you haven't already)
git clone https://github.com/Cirius1792/personal-site.git
cd personal-site

# Initialize the LoveIt theme submodule
git submodule update --init --recursive
```

### Run locally

```bash
hugo server
```

This starts Hugo's development server (usually at `http://localhost:1313`). The site has no markdown content files — everything is configured in `config.toml` and static assets live in `static/`. Changes to the config or static files are picked up automatically.

### Building

```bash
hugo
```

This generates the static site into the `public/` directory.

## How to deploy

### Automatic (recommended)

Push to `main` and the GitHub Action **`Deploy to Firebase Hosting on merge`** runs automatically:

1. Checkout the repo
2. Deploy the `public/` folder to Firebase Hosting

No manual steps needed — just commit and push.

```bash
git add .
git commit -m "Your change"
git push origin main
```

### Manual deploy

If you want to deploy manually (e.g. from your machine):

```bash
# 1. Install Firebase CLI if you haven't
npm install -g firebase-tools

# 2. Login
firebase login

# 3. Build the site
hugo

# 4. Deploy to Firebase
firebase deploy --only hosting
```

The Firebase project is `clt-personal-site` (configured in `.firebaserc`).

### Preview on PRs

The repo also has a **`Deploy to Firebase Hosting on PR`** workflow. When you open a pull request, Firebase generates a preview URL so you can review changes before they go live. This only triggers for PRs from the repo itself (not forks).

## Configuration

Everything is in `config.toml`. Key things you might want to change:

- **Profile / bio**: `[params.home.profile]` — title, subtitle, avatar URL
- **Social links**: `[params.social]` — GitHub, LinkedIn, Instagram, Email, etc.
- **Base URL / domain**: `baseURL` at the top of the file
- **Avatar image**: Place a new image in `static/` and update `avatarURL`

## File structure

```
personal-site/
├── config.toml          # Site configuration
├── firebase.json        # Firebase Hosting config (points to public/)
├── .firebaserc          # Firebase project reference (clt-personal-site)
├── archetypes/          # Hugo content templates (unused — no content pages)
├── assets/              # Hugo assets (images, etc.)
├── public/              # Built output (generated by Hugo, committed for deploy)
├── static/              # Static files served as-is (profile pics, etc.)
├── themes/              # Hugo themes (LoveIt via git submodule)
└── resources/           # Hugo generated resources (SCSS cache, etc.)
```

## GitHub Actions secrets

The deploy workflows require one secret to be set in the repo:

- **`FIREBASE_SERVICE_ACCOUNT_CLT_PERSONAL_SITE`** — a Firebase service account JSON key. Without this, the CI/CD pipeline can't authenticate with Firebase.
